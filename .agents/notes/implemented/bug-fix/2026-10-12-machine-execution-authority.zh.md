# 将云端执行绑定到机器权限和已认证内容

Status: implemented
Translation: current

[English](2026-10-12-machine-execution-authority.md)

## 摘要

工作区 MCP 和机器 Provider 配置通过共享文档同步，因此其他成员能修改不属于自己
的机器所读取的可执行配置。此修复保留机主从 Web 访问私有机器，同时要求其他成员
具有当前共享权限。云端消息与 RPC 带有绑定内容的认证凭证；私有机器使用本机可信
Provider 配置并拒绝工作区 MCP。共享机器仍按约定接受工作区可执行配置；持久化准入
后崩溃，可能需要用户发送新请求。

## 决策

行为见[草案规范](../../../../specs/machine-execution-authority.zh.md)。同步历史中声明的
`userId` 不能实现身份鉴别，身份必须来自认证服务。队列在写入时签名，经过历史写入
边界的规范化后分发验证，避免 Mirror 容器 ID 使晋升后的摘要变化。原生会话恢复的
默认目标也需要本机可信记录；原生恢复不可用时，私有机器不能回放未认证的共享历史。

Provider 保存前先规范化，再签名。私有机器最终启动、预启动、初始化探测和 Codex
账户冻结使用同一可信读取路径。有效机主更新替换本机配置，未签名的同伴修改不能
替换它。这避免引入通用 MCP 批准界面，同时让私有机器保持在工作区命令信任范围
之外。共享机器沙箱与完整 Provider 撤销机制属于独立决策。

## 验证

后续 MCP 修正已将私有机器的一律禁用改为机主认证的可执行版本与本机上次接受版本。
只有保存完整连接才申请新凭证，修改描述或默认开关不能替其他成员的命令授权；CLI
增量修改连接仅继承可信字段。签名内容将可执行版本与偏好修改时间分开。本机消息和
Provider 保存通过现有本机控制端点获取绑定机主的 HMAC 凭证，不依赖云端签发。
测试覆盖真实本机 handler、并发密钥初始化、凭证作用域、MCP 替换／回滚，以及真实
Flock writer 的默认开关授权边界。

进一步对抗审查发现 Provider 自动迁移、重试安装及 Pi 增量迁移可能给继承的成员
启动字段授权。通用写入现仅保留已有凭证，只有完整创建／编辑提交显式申请授权；
本地缓存读取已提交的带凭证记录。真实 Flock 回归测试覆盖这些写入方式。MCP 目录
读取失败时也可使用本机已接受版本，未知选择仍不执行。Pi 增量迁移的兼容性仍需与
下述工作流缺口一起处理。

这仍是未满足全部无回退要求的进行中补丁。旧数据迁移正在等待信任策略决定；远端
消息接受、离线 MCP 保存、私有历史回放和完整离线启动路径仍待处理。尚未进行完整
三端端到端测试或验证 Windows 管道访问权限。

机主审阅后的纠正：初版补丁虽已实现，但不满足保留 Web、桌面端和移动端正常体验的
要求。除了私有 MCP／Provider／历史回放限制，`authorizeTurn` 在本地 writer 接受
消息前等待托管鉴权，也影响双通道桌面工作区，违反原有本地／离线发送接受边界。
修订后的规范已记录这些缺口；不能将当前补丁描述为无体验损失。

行为测试覆盖机主／私有机器和成员／共享机器准入、撤销共享、内容篡改、通过真实
Loro 存储的队列编辑和晋升、私有 Provider 解析、持久化防重放。本地验证包含已有
启动和分发测试。本次补丁尚未进行托管多用户及真实 ACP 端到端执行验证。修复历史
回放绕过后，对抗审查在此权限策略范围内未发现剩余的已确认 P0/P1。未创建 PR。

全工作区类型检查、改动文件的类型感知 Lint、针对性回归测试、文档检查以及公开源码、
平台和导入边界检查均通过。`pnpm check:affected` 回退到全仓检查后，被未修改的
`docs/e2ee/x02` 和 `docs/e2ee/x03-platform` 脚本中已有的 Lint 错误阻塞，因此全仓
检查尚未通过。
