# 缺失会话 PR 关联的明确确认

Status: proposed
Translation: current
PR: [#1497](https://github.com/LodyAI/Lody/pull/1497)

[English](2026-10-12-missing-pr-association.md)

## 摘要

机器可能已经发布经过核验的 PR 摘要，但托管关联失败，导致 PR 标签页有链接却
无法确认会话的仓库身份。重试能补全已有且可证明的旧关联，不能根据 URL 或 PR
缓存还原缺失的原始关联。本改动让工作区管理员查看经过核验的当前 PR 后，明确
建立新关联。自动流程仍拒绝无法核验的身份，并保留 GitHub 授权检查；本改动不
恢复未知的历史来源。

## 决策与边界

仓库名称可能被复用，会话 PR 摘要仅包含 URL 和状态。当前缓存中的数字仓库 ID
能证明 PR 属于哪个仓库，不能证明历史会话原先属于哪个仓库。仅凭这些信息自动
补关联，可能把旧会话静默绑定到另一仓库。

服务端区分缺失关联与已有但未核验或冲突的关联。只有通过真实应用登录认证的
工作区所有者或管理员可以预览并确认新关联。预览核验当前 GitHub App、工作区、
仓库连接及实际 PR。确认比较同一仓库 ID 与 PR node ID，再在事务中重新核验
成员身份、删除屏障、仓库权限、安装的工作区归属和存活状态，以及冲突关联。
插入缺失关联，不替换旧关联或 PR 缓存。唯一且数字 ID 与当前核验相同的关联
幂等成功；若并发的 CLI 关联使用了改名后的仓库名称，确认仅更新查询别名，
保留绑定与创建时间。请求中的仓库名称作为查询别名保留；规范读取仍依据
不可变仓库 ID，仓库改名后也如此。

确认绑定应用登录、工作区、所属会话与 PR；切换任一目标后失效，确认失败必须
重新预览。普通重试不调用确认。界面明确说明这是用于详情及后续更新的新关联；
之后 webhook 分发可能更新 PR 元数据。后端不读取 Streams，也不确认会话是否
存在。界面使用当前选中的所属会话，离开后丢弃该预览。

另一方案是继续保持阻塞，直到机器完成关联协调。如果事先保存了不可变会话来源，
可以另行实现自动恢复协议，但历史记录没有这些事实。机器凭据读取回退，以及
按授权隔离的读取缓存，仍是独立工作。本修复未确认 issue #1378 在生产中被拒绝
的精确原因；测试在客户端和服务端边界复现缺失关联状态。

## 验证

行为测试覆盖已有数字 PR 缓存仍缺失关联、明确确认、改名后的规范读取、幂等、
未登录或普通成员、身份变化、角色和权限撤销及删除竞态、冲突记录。界面测试
覆盖详情读写阻塞、可见预览错误、明确确认，以及切换会话或登录后的过时预览。
夹具均为合成数据，验证不修改生产关联。
