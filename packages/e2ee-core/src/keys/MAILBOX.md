# Authenticated local mailbox reference

`@lody/e2ee-core/keys/mailbox/sqlite` creates a local reference host in the application's Effect Scope. It borrows a supplier of independently verified current ledger views and returns a `bind(principal)` session. The composition must authenticate that principal; request body/header identities cannot establish it. This package does not supply transport authentication or a production server.

The host admits only current eligible signed epoch envelopes through the fixed public verifier. Ciphertext is indexed by epoch/recipient/sender/digest. Re-appending the same ciphertext under new IDs adds no rows; a sender's conflicting existing ID fails. `read(id)` reads the original stored ID, so an attacker-created duplicate alias is not a delivery acknowledgement. `fetch` loads/copies at most the requested 100 ciphertext rows using a bounded SQLite query, never one globally decoded stream. An indexed scalar EXISTS after the last sender/digest decides the next hint without loading a lookahead frame. Discovery cursors are offsets over the current projection, not durable transport positions or an atomic snapshot across requests; changing projections require rediscovery. Old-epoch slots are obsolete hints; ciphertext/history remains retained.

`@lody/e2ee-core/keys/reports` retains canonical key-installed/v1 report bytes. A report is a recipient-signed claim bound to Org, current epoch/commitment, source and repair revision. It proves neither actual key persistence nor honest server storage. The host separately checks authenticated recipient, real current authority, stored usable source digest or exact verified local-publication record, and current revision. A local publication whose historical hash is unknown to an endorsed snapshot cannot be assumed verified. Repair is recipient-only and idempotent per request ID; rejected ciphertext is excluded from fetch, retained for audit, and a repair invalidates the prior reported revision. Lost-key repair can retain usable ciphertext.

Create requires an absolute path and creates exclusively with 0600. Open requires the separate indexed application ID 0x4c454d32 and version 1; it never imports/converts the old JSON mailbox ID 0x4c454d31. WAL/FULL immediate transactions retain exact bounded ciphertext and reports. Public ledger head/count observations persist independently of document/transport cursors and prevent reopening against known older/forked authority. The supplier's external authenticity and freshness still belong to composition; there is no cross-stream transaction.

Scope closes the SQLite handle without deleting history. Operations check closure again after a borrowed async lookup, so late completion cannot write through a closed host. No fiber or Runtime is created. The caller must structure, cancel and await its own requests and borrowed transport/ledger resources; host close does not claim cancellation of escaped work. No transaction is held during async lookup/crypto. Corrupt rows fail in the affected read; unrelated recipient rows remain readable.

Run `pnpm --filter @lody/e2ee-core exec vitest run test/keys/mailbox.test.ts`. Tests use actual Ed25519/HPKE and SQLite, synthetic keys, deterministic Deferred signals and database reopen. They do not establish recipient durable installation, HTTP authentication, legacy global-stream compatibility, Lab completion, production E2EE, native custody or power-loss acceptance. Distribution/receive workflows remain separate migration owners.
