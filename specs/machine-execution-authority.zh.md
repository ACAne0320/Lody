# 机器执行权限

Status: draft
Translation: current

[English](machine-execution-authority.md)

机主可以从 Web、桌面端和移动端向未共享机器发送消息。其他工作区成员只有在机主共享机器时才能
在其上执行。共享机器表示接受工作区的可执行配置，包括工作区 MCP；加入工作区
本身不代表授予机器执行权限。

## 修订后的验收要求

机主要求所有客户端保留正常流程，包括 MCP、已有 Provider、会话恢复以及桌面端本机
离线发送。全面禁用私有机器功能，或在本地消息接受前等待云端鉴权，均不符合要求。
不能因为使用本机通道就降低鉴权：同步文档内容不能证明实际作者或传输来源。

当前实现尚未满足全部验收要求。配置在明确保存连接时获得授权，普通发送和默认开关
不能隐式批准命令。旧的未签名配置如何迁移仍未确定：无感沿用现有副本意味着接受
升级前已被污染的可能性，不能通过 `createdBy` 重建可信作者。本次未选定迁移策略。

## 当前实现（仍需修订）

云端客户端为消息和 Machine RPC 获取绑定具体内容的身份凭证，daemon 在分发前
验证凭证和机器当前权限。同步文档里的用户 ID、默认选项和已完成标记，均不能作为
身份、执行同意或防重放依据。纯本地模式使用本地通道，不调用云端鉴权。CLI 代为
发起请求时，CLI 凭证所属用户和实际驱动消息的用户都必须拥有目标访问权限。

桌面本机消息和 Provider 保存通过现有操作系统本机控制通道获取本机密钥凭证，绑定
daemon 机主、目标和内容，不需要云端签发。这不等于信任本机收到的同步文档。
远端发送仍同步等待托管鉴权；Web／移动端的离线本地接受和完整桌面启动路径仍待处理。

私有机器使用经过机主认证保存的 MCP 可执行版本，或本机上一次接受的版本。其他成员
替换、删除目录行或回放旧版本不能替换可信命令。保存完整连接才能授权新版本，修改
描述或默认开关不能。CLI 修改连接只继承可信字段。尚未批准的 MCP 被跳过，不再
拒绝整个会话。Provider 使用本机创建或机主明确保存的可信配置。
未定制的内置 Provider 可以从本机静态实现初始化；自定义命令、运行时覆盖、环境
变量和账户绑定不能这样信任。准备会话、恢复会话和能力探测遵守相同规则。私有机器
禁用工作区 GitHub 初始化和清理脚本，本机项目脚本仍来自本地配置。原生会话恢复的
默认目标来自本机记录，不采用可被其他成员修改的同步元数据。原生恢复失败时，私有
机器也拒绝自动回放未认证的工作区历史。

凭证绑定目标机器和执行内容。编辑队列后重新签名，晋升消息与签名使用同一套内容
规范化规则。本机持久化记录使每个 RPC／消息 ID 只获得一次执行准入；准入后崩溃
可能需要发送新请求，不能重放可能已经执行的命令。取消共享阻止新的执行准入，
不会终止已经启动的进程。

## 兼容性与限制

先部署鉴权端点，再部署对应客户端和 daemon。旧版未签名云端请求被拒绝，需升级后
重新发送。旧的定制 Provider 和未签名 MCP 尚无迁移策略。云端鉴权依赖后端可用。
本机保留已批准的 Provider 配置，这不是完整的
批准／撤销界面，也不是共享机器沙箱。已共享机器按照约定继续允许工作区命令执行。
