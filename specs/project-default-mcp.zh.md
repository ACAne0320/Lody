# 项目默认 MCP 选择

Status: draft
Translation: current

[English](project-default-mcp.md)

## 场景与范围

用户打开项目的「默认 MCP」Tab，查看当前工作区注册的 MCP，通过开关设置该项目
对话的默认选择。建议首版用于新对话的预选，包含从 CLI/MCP 入口创建的首轮。
已有对话保留自己的选择；修改项目默认项不改变已接受或运行中的轮次。
本文是提案，尚未实现或批准。

## 数据归属

工作区目录仍是 MCP 名称和连接配置的唯一来源。同一个工作区 Flock 文档新增项目
偏好数据族，只存项目身份、MCP id 与开启/关闭覆盖值，不存连接或凭据。
实际选择继续存于每轮 `inputConfig.mcpServerIds`，运行时只消费这份冻结选择。

项目身份不包含分支、会话或 Worktree 路径。本地项目用 machine id 加 local project id；
GitHub 项目使用工作区内规范化的仓库身份。本地目录即使有 GitHub remote，也仍然是
独立的本地项目，不隐式合并两类身份。这里的机器字段只标识本地项目，不是 MCP
连接的机器绑定，也不代表该机器已具备运行条件。

项目偏好沿用项目现有的管理授权；读写验证工作区和项目范围。存储可见性不等于
保密保证。公开本地桌面通过已有本地 repo/platform 端口访问，不依赖认证产品云请求。

## 选择语义

对每个 MCP，项目覆盖值优先于目录 `enabledByDefault`；无覆盖值时继承工作区默认。
开关展示最终值，点击写显式布尔值；「恢复工作区默认」删除项目覆盖。
后来注册的 MCP 继承其工作区默认，除非该项目明确覆盖。

写入轮次时的优先级：

1. 本次发送的显式选择，包括空数组。
2. 续聊时目标对话已有的选择。
3. 新对话的项目/工作区有效默认项。

历史对话未记录选择时视为空，不追溯应用项目默认。没有项目的对话使用工作区默认。
Fork、编辑重发默认保留来源选择；真正新建的委派对话使用目标项目默认，除非调用方
显式提供 ids。Role 不存 MCP ids，也不隐式将调用方项目的选择复制给其他项目。

默认项在发送或 Operation 接受前解析，解析出的 ids（包括 `[]`）在 dispatch 前冻结
到接受的请求和对应轮次。重试、排队、附件延迟发送及恢复使用这份 ids。
启动时不重新叠加项目默认。只冻结 ids；连接配置和目标运行能力仍在启动时从当前
目录和运行时解析。

## 界面与失败行为

「默认 MCP」位于「技能」和「对话」之间。每行显示名称、描述、传输类型、配置状态
及开关。提供搜索、已选数量、恢复默认和工作区 MCP 管理入口，不展示连接秘密。
说明默认项用于新对话，发送前可在输入框调整。目录为空时展示管理入口，不能把
空状态误写为项目策略。

草稿选择按工作区和项目隔离，切换任一身份时重置此前项目的临时覆盖。
偏好写入以本地持久化为成功点；支持上传的平台随后独立上传。写失败回退对应行
并报错。并发修改不同 MCP 不能互相覆盖。只读用户可查看，不能切换或恢复默认。

接受依赖默认项的发送前，应得到就绪的本地策略/目录快照。加载中或读取错误不能
当成空列表。附件上传期间修改项目配置，不改变点击发送时已冻结的选择。
目录中已删除的 id 保持可诊断，绝不能按同名条目重新绑定。无效连接、不支持的
传输沿用现有运行时问题报告。开启表示已选择，不代表已连接、已授权或成功加载。

## 兼容与验收

增加支持默认项写入的版本化机器协议能力。对不支持的写入路径，新客户端不能声称
默认项正常生效；已冻结的显式选择仍可走兼容的既有 dispatch。旧客户端必须保留
未知偏好行；旧客户端省略选择时，不能在运行时偷偷重新解释。通过混合版本测试验证。

验收覆盖：优先级（尤其 `[]` 和项目显式关闭）、本地/GitHub 身份隔离、Worktree
继承、读写授权、加载与持久化失败、并发行编辑、UI/CLI/MCP 写入一致性、附件延迟
发送/重试/恢复、预热缓存身份与运行时重建、删除/改名、不支持的传输，以及本地零
产品云请求。

首版仅影响新对话仍是待确认的产品提案。若要求已有对话动态继承，需要独立的
继承/覆盖契约，不能通过无条件合并 ids 实现。
